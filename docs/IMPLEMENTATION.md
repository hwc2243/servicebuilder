# IMPLEMENTATION.md: Template & Generator Architecture

## 1. Directory Hierarchy
The FreeMarker templates (`.ftl`) used by the engine must be organized in the following directory tree:

```text
/templates
    └── java/
        ├── model/
        │   ├── BaseModel.ftl
        │   └── ExtensionModel.ftl
        ├── entity/
        │   ├── BaseEntityImpl.ftl        
        │   └── ExtensionEntityImpl.ftl
        ├── persistence/
        │   ├── BasePersistence.ftl
        │   └── ExtensionPersistence.ftl
        ├── dto/
        │   ├── BaseDTOImpl.ftl
        │   └── ExtensionDTOImpl.ftl
        ├── service/
        │   ├── BaseService.ftl
        │   ├── BaseServiceImpl.ftl
        │   ├── ExtensionService.ftl
        │   └── ExtensionServiceImpl.ftl
        └── api/
            ├── internal/
            │   ├── BaseInternalRest.ftl
            │   ├── BaseInternalRestImpl.ftl
            │   ├── ExtensionInternalRest.ftl
            │   └── ExtensionInternalRestImpl.ftl
            └── external/
                ├── BaseExternalRest.ftl
                ├── BaseExternalRestImpl.ftl
                ├── ExtensionExternalRest.ftl
                └── ExtensionExternalRestImpl.ftl

## 2. Template Mapping Logic
The generator must resolve paths using the following logic:

- **Base Components:** Target path is always {PackageName}.{layer}.base. These files are volatile.

- **Extension Components:** Target path is {PackageName}.{layer}. These files are stable.

- **API Visibility:** If the XML defines <internal>, use templates from api/internal/. If <external>, use api/external/.

## 3. File Existence Policy
- **Volatile Files (Base):** The generator must overwrite these files regardless of existing content to ensure sync with the XSD/XML.

- **Stable Files (Extension):** Before processing any Extension*.ftl template, the engine MUST check if the target .java file already exists. If it exists, the generation for that specific file must be skipped.

## 4. Generator Constraints
- **Template-Mandatory Generation:** Every source file generated by the Service Builder (Interfaces, Base Classes, and Extension Classes) MUST be produced via a FreeMarker (`.ftl`) template.
- **No Hardcoded Logic:** The generator engine is prohibited from hardcoding class structures. All architectural patterns (Generation Gap, Interface-First) must be defined within the `.ftl` templates.
